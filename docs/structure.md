# Структура и анатомия аддона

В NanoForge каждый аддон — это изолированная **папка** с конфигурацией, данными и дампом целевого API.

---

## 📁 Файловая иерархия плагина

```
plugins/NanoForge/
  ├── addons/
  │   └── MyAddon/
  │       ├── addon.yml         # Основной файл конфигурации: команды, события, меню
  │       ├── storage.yml       # Постоянное хранилище переменных и кулдаунов (создаётся автоматически)
  │       ├── target-api.txt    # Автодамп классов и методов целевого плагина (только для type: addon)
  │       └── backups/          # Автоматические бэкапы addon.yml перед изменениями из игры
  │           ├── addon-2026-10-05_12-00-00.yml
  │           └── ...
  ├── exports/                  # Сюда сохраняются .zip-архивы при выполнении /nano export
  └── imports/                  # Сюда помещаются архивы для выполнения /nano import
```

---

## 📄 Спецификация `addon.yml`

Файл `addon.yml` описывает поведение аддона. Пример полной структуры:

```yaml
name: SuperRewards
type: addon                   # addon (привязка к плагину) или new (автономный)
target: Vault                 # Имя целевого плагина (обязательно для type: addon)
enabled: true                 # Состояние: включён или выключен

# Зависимости от других аддонов NanoForge (опционально)
requires:
  - BaseCore
  - EconomyHub

# Динамические команды Bukkit
commands:
  rewards:
    description: "Открыть меню ежедневных наград"
    permission: rewards.use   # Необязательное право на вызов команды целиком
    actions:
      - type: openmenu
        menu: main

# Слушатели событий Bukkit
events:
  PlayerJoinEvent:
    actions:
      - type: message
        text: "&eС возвращением, {player}! Напиши /rewards для получения бонуса."

# Инвентарные GUI-меню
menus:
  main:
    title: "&8Награды сервера"
    rows: 3
    items:
      "13":
        material: GOLD_BLOCK
        name: "&6Ежедневный бонус"
        actions:
          - type: eco_give
            amount: 500
          - type: message
            text: "&aВы получили 500 монет!"

# Триггеры Citizens NPC
npcs:
  reward_giver:
    npc_id: 12
    actions:
      - type: openmenu
        menu: main
```

## 🏷️ Типы аддонов: `addon` против `new`

| Параметр | `type: addon` | `type: new` |
|---|---|---|
| **Назначение** | Расширение существующего плагина | Самостоятельный мини-плагин |
| **Поле `target`** | Обязательно (имя плагина в Bukkit) | Не требуется |
| **Target Inspector** | Создаёт `target-api.txt` со списком методов | Не создаётся |
| **Проверка зависимостей** | Не включится через `/nano enable`, если плагин отсутствует или выключен | Работает автономно |

## 🔗 Межаддонные зависимости (`requires`)

Аддоны могут зависеть друг от друга с помощью секции `requires`:

```yaml
requires:
  - CoreDatabase
  - AuthManager
```

### Как работает загрузка:
1. **Двупроходная инициализация:** На старте сервера NanoForge сначала считывает все `addon.yml` в память, и только потом активирует те, у которых `enabled: true`. Это исключает ошибки порядка загрузки из-за алфавитного порядка папок на диске.
2. **Строгая проверка при ручном включении:** Если вы выполните `/nano enable MyAddon`, а зависимый аддон выключен или отсутствует, включение будет безопасно заблокировано с подробным сообщением в консоль и чат.
3. **Мягкая проверка при старте сервера:** При старте сервера выводится предупреждение, позволяющее зависимостям подняться в процессе запуска.

## 💾 Хранилище `storage.yml`

Создаётся и управляется автоматически. В нём сохраняются:
* Переменные игроков: `players.<UUID>.<ключ>`
* Глобальные серверные переменные: `global.<ключ>`
* Таймстемпы кулдаунов: `cooldowns.<ключ>.<UUID>` (и глобальные `__global__`)

> [!TIP]
> Состояния двойного клика (`confirm`) хранятся исключительно в оперативной памяти (In-Memory) и не засоряют диск.

---

## 🛡️ Автоматические бэкапы (`backups/`)

NanoForge реализует встроенную систему контроля версий конфигураций:
* Перед **любой** модификацией файла через команду `/nano set` или через встроенный редактор меню (`/nano edit`), текущее состояние `addon.yml` копируется в `addons/<имя>/backups/addon-ГГГГ-ММ-ДД_ЧЧ-ММ-СС.yml`.
* Система автоматически хранит **до 20 последних ревизий** для каждого аддона, удаляя устаревшие.
* Если администратор случайно повредил конфигурацию в игре, он может мгновенно восстановить любой предыдущий бэкап.

## 📦 Экспорт и импорт аддонов

Вы можете легко упаковывать аддоны для переноса между серверами или публикации:

### Экспорт:
```shell
/nano export MyAddon
```
* Создаёт компактный архив: `plugins/NanoForge/exports/MyAddon.nanoaddon.zip`.
* В архив включаются `addon.yml` и `target-api.txt`. Файл `storage.yml` намеренно исключается, чтобы не переносить историю игроков.

### Импорт:
1. Поместите `.nanoaddon.zip` в папку `plugins/NanoForge/imports/`.
2. Выполните команду:
```shell
/nano import MyAddon.nanoaddon.zip NewAddonName
```
3. Импортированный аддон появится в `addons/` и стартует в выключенном состоянии для безопасной проверки конфигурации перед включением.
