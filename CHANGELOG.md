# Changelog

## 1.0.0

Первый набор фич.

### Основное
- `/nano create addon <плагин> <имя>` / `/nano create new <имя>` — создание
  аддонов и самостоятельных мини-плагинов, описываемых в YAML.
- Табкомплит по реально загруженным плагинам сервера для `create addon`.
- `/nano enable|disable|list|info|reload` — управление аддонами без рестарта.
- Динамическая регистрация команд и событий (без объявления в `plugin.yml`).
- Полный `unregister` событий и команд при выключении/повторном включении
  аддона (идемпотентно — без утечек и задвоенной регистрации).
- Дамп классов/методов/полей целевого плагина в `target-api.txt` при
  создании аддона (через рефлексию, для написания `type: call`).

### GUI-меню
- Инвентарные меню (`menus:` в `addon.yml`), с произвольной вложенностью
  через `openmenu`/`closemenu`.
- Видимость пунктов по правам/миру/региону (`if:` на самом пункте).
- Редактор меню в игре: `/nano edit` — перетаскивание предметов задаёт
  иконку кнопки, shift-клик по кнопке открывает ввод её логики через чат
  (простой DSL: `message`, `call`, `openmenu` и т.д.).

### Движок действий
- `actions`: `message`, `broadcast`, `console`, `call`, `openmenu`,
  `closemenu`, `setvar`, `addvar`, `eco_give`, `eco_take`.
- `if`-условия: `permission`, `not_permission`, `world`, `region`,
  `eco_at_least`, `var_equals`, `var_at_least`, `cooldown`.
- Плейсхолдеры `{player} {uuid} {world} {x} {y} {z} {health} {level}` и
  `{result}` (результат последнего `call`, опционально сохраняемый через
  `save_as` в переменную аддона).
- Хранилище переменных/кулдаунов на аддон (`storage.yml`).

### Интеграции (опционально, через рефлексию — без жёсткой зависимости)
- Vault (экономика): `eco_give`/`eco_take`/`eco_at_least`.
- WorldGuard 7.x (регионы): `if: region`.
- Любой другой плагин сервера: `type: call` + `target-api.txt`.

### Надёжность
- Один битый `addon.yml` не роняет загрузку остальных аддонов и старт сервера.
- `softdepend: [Vault, WorldGuard]` в `plugin.yml` для корректного порядка загрузки.

## 1.0.1

Первая реально собираемая версия — доводка до рабочего состояния перед публикацией.

- Vault/WorldGuard теперь пишут одно понятное предупреждение в консоль при
  первом реальном использовании, если сами не установлены (раньше — тишина).
- Интеграция с PlugMan/PlugManX: если целевой плагин аддона установлен, но
  выключен, `/nano enable` и `/nano info` предлагают игроку кликабельную
  кнопку "Включить" в чате.
- Исправлено: `/nano enable` теперь корректно отличает "плагин не найден"
  от "плагин найден, но выключен" (раньше выключенный-но-установленный
  плагин ошибочно считался достаточным для включения аддона).
- Проверка версии сервера при старте: диапазон 1.16 – 1.21.11, с понятным
  предупреждением (не блокировкой) если сервер ниже или выше.
- Баннер с контактом автора при каждом включении плагина.
- `.github/workflows/ci.yml` — сборка и прогон тестов на каждый push/PR.
- `.github/workflows/release.yml` — автоматический релиз на push в
  main/master: версия и тег берутся напрямую из `plugin.yml` через GitHub
  API, без ручного ввода версии и без дополнительных секретов (только
  встроенный `GITHUB_TOKEN`).
- Полный тестовый стек в `pom.xml`: JUnit 5, Mockito, AssertJ.
- Юнит-тесты: парсер чат-DSL, плейсхолдеры, условия `if` (права/мир/
  переменные/кулдауны), хранилище переменных, безопасное поведение
  интеграций без Vault/WorldGuard/PlugMan, границы поддерживаемых версий.
- Исправлена ошибка сборки: `spigot-api 1.20.4` скомпилирован под Java 17
  (class file version 61), поэтому CI и `pom.xml` (`maven.compiler.release`)
  теперь используют JDK 17 для сборки — при этом собранный плагин остаётся
  на байткоде Java 8 и грузится на старых 1.16-серверах.
- Исправлен реальный баг в `AddonStorage.getVarNumber`/`getGlobalVarNumber`:
  `setVar` всегда пишет значение как строку, а обычный
  `YamlConfiguration.getDouble()` не парсит строки и молча возвращает
  дефолт — из-за этого `var_at_least` мог ложно не проходить для чисел,
  сохранённых через `setvar`/`addvar`. Теперь число читается вручную
  (`Double.parseDouble`) независимо от того, как оно хранится в YAML.
- Исправлен `StartupChecks.classify`: полностью нераспознаваемая строка
  версии (например, кривая сборка сервера без нормального номера) раньше
  тихо превращалась в "0.0.0" и ошибочно классифицировалась как "версия
  ниже минимальной" — теперь корректно возвращает `UNKNOWN`.
- Поправлены сами тесты: `PlaceholderUtilTest` — стабы в `@BeforeEach`
  помечены `lenient()`, так как не каждый тест их использует (иначе
  Mockito ругается `UnnecessaryStubbingException`).
- Исправлен off-by-one в `AddonStorage.remainingCooldownSeconds`: округление
  оставшегося времени вверх (`+1` к целым секундам) завышало результат на
  целую секунду, если остаток был ровно кратен 1000мс (например, сразу
  после `markCooldown` для 30-секундного кулдауна возвращалось 31, а не 30).
  Заменено на настоящее округление вверх через `(remainingMs + 999) / 1000`.
- MockBukkit ещё раз попробован и снова убран: репозиторий PaperMC починил
  резолв, но выявилась несовместимость версий в рантайме —
  `MockBukkit-v1.20:3.9.0` падал с `NullPointerException` при инициализации
  `PotionEffectType` из-за несовпадения с `spigot-api 1.20.4`. Без доступа
  в интернет надёжно подобрать совместимую версию нельзя, поэтому
  интеграционный тест целого плагина (`PluginIntegrationTest`) удалён —
  тестируется изолированная логика через точечные моки Mockito, без
  эмуляции всего сервера.
- Добавлен `FancyFont` — оформление сообщений плагина игроку в чате
  (`/nano`, редактор меню) стилизованным unicode-шрифтом (мелкие капсы) и
  несколькими "нормальными" символами-декорациями (★ ➤ • ✔ ✖ ⚠). Таблица
  шрифта построена из присланного файла через unicode-эскейпы, без ручного
  перепечатывания глифов. Консольный лог и содержимое `addon.yml`,
  написанное самим создателем аддона, шрифтом сознательно НЕ трогаются.
- Почищены предупреждения компилятора "uses unchecked or unsafe
  operations": `@SuppressWarnings("unchecked")` в `DynamicListener` стоял
  не на том методе (на `register()`, а непроверенные касты — в вызываемом
  `resolveEventClass()` — подавление не наследуется на вызываемые методы,
  поэтому warning всё равно печатался). Перенесено туда, где нужно.
- Исправлена реальная ловушка в `FancyFont`: стилизация текста с
  плейсхолдером (`{player}` и т.д.) ломала последующую подстановку —
  `PlaceholderUtil` ищет точную строку `"{player}"`, а после стилизации
  букв внутри фигурных скобок она переставала совпадать. Теперь `{...}`
  защищены целиком, как и цветовые коды.
- Декоративные символы (★ ➤ ✔ ✖ ⚠) добавлены и в сгенерированный шаблон
  меню (`/nano create` создаёт пример с уже оформленными иконками/
  заголовками) — без полной стилизации букв, поскольку это контент,
  который создатель аддона будет редактировать сам.

## 1.1.0

Первый прогон на настоящем живом сервере (Paper 1.20.4) вместо
мок-библиотек — нашёл реальный баг, который никакие юнит-тесты по
отдельным кускам логики поймать не могли.

- **Исправлен серьёзный баг**: `/nano reload` необратимо выключал (и
  сохранял на диск `enabled: false`) вообще все аддоны, даже те, что были
  явно включены через `/nano enable`. Причина: `reloadAll()` вызывал
  `disableAll()`, которая персистила `enabled=false` в `addon.yml` перед
  тем, как `loadAll()` перечитывал тот же файл — reload буквально читал
  состояние, которое сам же секунду назад испортил. Теперь `disableAll()`
  (используется только для reload) лишь снимает регистрацию в Bukkit, не
  трогая сохранённый на диске флаг — обычный `/nano disable` по-прежнему
  корректно гасит и сохраняет `enabled: false`, это разные сценарии.
- Добавлен `AddonManagerTest` с тремя регрессионными тестами на этот
  сценарий (enable→reload сохраняет состояние; explicit disable всё ещё
  персистит выключение; reload не включает то, что было выключено).
- Подтверждено живым сервером: полный цикл `create → enable → info →
  reload → list → info` через консоль реального Paper-сервера отрабатывает
  корректно, включая создание `addon.yml`/`target-api.txt`, отображение
  статуса, обработку отсутствующего целевого плагина.

## 1.2.0

Первая версия, для которой часть проверок сделана не только юнит-тестами и
живым сервером через консоль, но и **настоящим игроком**: написан
минимальный клиент протокола Minecraft (Handshake → Login → Configuration
→ Play, MC 1.20.4), который заходит на сервер как реальный `Player` и шлёт
команды — использован для проверки того, что раньше было принципиально
недоступно без него (команды аддонов, требующие `sender instanceof Player`).

### Новые actions
- `give_item` — выдать предмет в инвентарь игрока (`material`, `amount?`,
  `name?`, `lore?`). `material`/`amount` тоже проходят через плейсхолдеры —
  можно писать `material: "{arg1}"` для выдачи предмета по аргументу команды.

### Новые условия
- `if: time` — игровое время мира игрока (тики 0-24000), с поддержкой
  диапазона "через полночь" (`min > max`).

### Новые плейсхолдеры
- `{args}` — все аргументы команды аддона одной строкой.
- `{arg1}`, `{arg2}`, ... — отдельные аргументы по номеру.

### Новые команды
- `/nano duplicate <аддон> <имя>` — клонировать аддон под новым именем
  (копия всегда стартует выключенной).
- `/nano export <аддон>` — упаковать аддон в переносимый `.zip`.
- `/nano import <файл.zip> <имя>` — импортировать аддон из
  `plugins/NanoForge/imports/`.

### Новая интеграция
- **PlaceholderAPI** — если установлен, его `%плейсхолдеры%` от любых
  других плагинов подставляются в любом тексте actions, в дополнение к
  своим `{player}`/`{world}`/... (через рефлексию, без жёсткой зависимости,
  как и Vault/WorldGuard/PlugMan).

### Фиксы и улучшения
- `target-api.txt` теперь фильтруется по пакету самого плагина (первые два
  сегмента пакета главного класса) — шейднутые в jar сторонние библиотеки
  (`com.google`, `org.yaml` и т.д.) больше не засоряют дамп.
- GUI-меню аддона теперь автоматически закрывается у всех, у кого оно
  открыто, если аддон выключается/удаляется — вместо того чтобы оставлять
  клик по кнопке ссылающимся на логику, которой уже нет.
- Исправлена реальная хрупкость в `PlaceholderUtil`: раньше ВСЕ поля игрока
  (`getUniqueId()`, `getWorld()`, `getLocation()` и т.д.) вызывались
  безусловно, даже если ни один плейсхолдер не встречался в тексте — теперь
  каждое поле трогается, только если его плейсхолдер реально есть в строке
  (заодно `getLocation()` теперь вызывается один раз вместо трёх для x/y/z).
- `.github/workflows/ci.yml`: второй job — живой smoke-тест на настоящем
  Paper-сервере (create → enable → reload → list через консоль, с проверкой
  файлов на диске) — целенаправленная регрессионная защита от повторения
  бага reload из 1.1.0, а не дублирование юнит-тестов.
- Тесты: `ActionRunnerTest` (give_item, подстановка args), новые кейсы в
  `ConditionCheckerTest` (time), `AddonManagerTest` (duplicate/export/
  import), `PlaceholderUtilTest` (args), `IntegrationBridgesTest`
  (PlaceholderAPI) — итого 113 тестов, все зелёные.

  метод и метод, бросающий исключение — раньше самый используемый в реальных

## 1.4.0

### Новое
- Action `title` — title/subtitle (с настраиваемыми `fadein`/`stay`/`fadeout`
  в тиках) и/или строка в actionbar; любую часть можно опустить (например,
  только `actionbar`). Поддерживает `{result}` и остальные плейсхолдеры.

### Тесты
- Закрыт пробел в покрытии, оставшийся с 1.3.0: `play_sound` и `teleport`
  не имели ни одного теста, хотя оба - в проде с прошлой версии. Добавлено
  8 тестов (успешный/некорректный звук, телепорт в текущий/именованный/
  несуществующий мир, все три варианта `title`).
- `MenuManagerTest` - открытие меню (в т.ч. видимость по `if: permission`),
  клик по кнопке, клик по пустому/чужому инвентарю - раньше проверялось
  только косвенно live-тестом.
- `AddonValidatorTest` - 11 тестов на новую команду `/nano validate`.
- Итого **150/150 тестов**.

### Новое (доразобрано по фидбеку, версия та же - 1.4.0)
- Action `delay` - выполнить вложенный список `actions` через N тиков
  (`{ ticks: 20, actions: [...] }`). `{result}` внутри НЕ наследуется из
  actions до delay - отсчёт начинается заново.
- Condition `confirm` - требует ДВА клика/запуска подряд от одного игрока
  в течение `seconds` (`{ seconds: 10, key: "delete" }`); первый всегда
  проваливает и показывает `deny_message`, второй проходит. Для необратимых
  кнопок (снос базы, банвайп и т.п.) вместо обычного `cooldown`.
- Команды `/nano get <аддон> <путь>` и `/nano set <аддон> <путь> <значение>`
  - точечное редактирование любого скалярного значения в addon.yml прямо из
    игры/консоли, без открытия файла. Табкомплит на пути показывает ВСЕ
    вложенные ключи YAML (`menus.main.items.10.material` и т.п.), а
    табкомплит на значении подставляет то, что там СЕЙЧАС лежит - тыкнул
    Tab, увидел текущее значение, поправил одну букву вместо перепечатывания
    заново. Списки/секции (`lore`, `actions` целиком) им не редактируются -
    для них `/nano edit` или сам файл.
- Команда `/nano validate <аддон>` - проверяет addon.yml БЕЗ загрузки: ссылки
  `openmenu` на несуществующие меню, неизвестные `material`, слоты вне
  диапазона меню, неизвестный `type` у action (защита от опечаток типа
  `mesage`), нерезолвящиеся `events:`, `delay` без вложенных `actions`.
  Разница ERROR/WARN - ERROR почти наверняка сломает работу, WARN стоит
  перепроверить, но может быть осознанным (например, событие стороннего
  плагина по полному пути класса).

### Исправлено
- **Команды новых/только что включённых аддонов не доходили до реальных
  игроков** - работали из консоли/RCON, но игрок получал "Unknown command".
  Причина: динамическая регистрация в `SimpleCommandMap` не обновляла
  Brigadier-дерево команд у уже подключённых клиентов. Теперь после
  включения/выключения аддона `AddonManager` дополнительно вызывает
  `CraftServer.syncCommands()` через reflection (сам метод - деталь
  реализации конкретной версии сервера, не часть публичного Bukkit API,
  поэтому не даёт скомпилироваться напрямую; на версиях без него просто
  ничего не делает). Баг был живым все прошлые версии, просто не
  проявлялся в тестах на моках и вручную через консоль.

### PlaceholderAPI-экспансия
- NanoForge теперь не только читает чужие `%плейсхолдеры%` (это было и раньше,
  чистой рефлексией), но и отдаёт СВОИ переменные наружу: `%nanoforge_<аддон>_<ключ>%`.
  `<ключ> = enabled` → `true`/`false` (включён ли аддон); любой другой ключ →
  сначала персональная переменная игрока (`setvar` без `addon:`), иначе
  глобальная (`addvar`/`setvar` в общий неймспейс), иначе пустая строка.
  Имя аддона - всё до ПЕРВОГО `_` в параметре, поэтому для этой фичи аддоны
  нужно называть без подчёркиваний (CamelCase, как в примерах).
- `PlaceholderExpansion` - абстрактный класс, а не интерфейс, поэтому (в
  отличие от Vault/WorldGuard/CachesManager и т.п., куда NanoForge стучится
  чистой рефлексией без единой зависимости) тут пришлось добавить
  `me.clip:placeholderapi:2.12.3` в `pom.xml` как `provided`-зависимость -
  в `NanoForge.jar` она не попадает, а на сервере без самого PlaceholderAPI
  (он теперь в `softdepend`, не `depend`) всё остальное как обычно работает.
- 9 новых юнит-тестов на `NanoForgeExpansion` (неизвестный аддон, `enabled`,
  приоритет личной переменной над глобальной, пустая строка по умолчанию).
  Итого **158/158**.
- Полноценно погонять вживую с реальным PlaceholderAPI не вышло: конкретный
  jar с `repo.extendedclip.com` (maven-артефакт, не сборка со страницы
  Spigot) не шьёт bStats внутрь и падает на старте с `NoClassDefFoundError`
  в тестовом окружении - это особенность самого стороннего jar'а, не
  NanoForge. Логику экспансии это не отменяет (она вся живёт в 9 тестах
  выше), но перед боевым использованием стоит проверить `%nanoforge_...%`
  на своём сервере с обычной сборкой PlaceholderAPI со Spigot/Polymart.
- **Важный фикс уже после написанного выше**: простой вызов
  `NanoForgeExpansion.tryRegister(...)` из `onEnable()` заставлял JVM
  грузить класс `NanoForgeExpansion`, а значит и его родителя
  `PlaceholderExpansion` - БЕЗ PlaceholderAPI на сервере это ронял NanoForge
  целиком на старте (`NoClassDefFoundError`), даже с внутренней проверкой
  "плагин установлен?" - проверка не успевала сработать, потому что сам
  факт упоминания класса-наследника уже требовал загрузки родителя.
  Исправлено переносом проверки `Bukkit.getPluginManager().getPlugin(...)`
  СНАРУЖИ, в `onEnable()`, до первого упоминания `NanoForgeExpansion` где
  бы то ни было. Живой сервер без PlaceholderAPI на этой версии проверен -
  включается чисто.

### Shift-click и многострочный чат-DSL (закрыты оба старых "Известных ограничения")
- **Vanilla shift-click теперь тоже отслеживается.** Раньше в `/nano edit`
  сохранялось только прямое перетаскивание предмета на конкретный слот - а

  (по ванильной логике "в первый свободный слот"), но addon.yml об этом не
  узнавал. Теперь перед обработкой такого клика снимается снимок верхнего
  инвентаря, а на следующем тике - сравнение с результатом; все
  изменившиеся слоты (может быть больше одного, если предмет ещё и
  доукомплектовал существующие стопки) сохраняются как обычно. Проверено

  `DIAMOND` автоматически.
- **Чат-DSL редактор меню теперь поддерживает несколько actions на пункт.**

  shift-клик по кнопке в `/nano edit` → `message ...` → `broadcast ...` →

### Фикс сборки (найден по реальному GitHub Actions, не локально!)
- `mvn clean verify` в CI падал на `testCompile`: `List.of(...)` в тестах —
  Java 9+, а `maven.compiler.release=8` в `pom.xml` (нужен для совместимости
  вывода плагина со старыми версиями сервера) применяется maven-compiler-plugin'ом
  **и к тестам тоже**, если не сказать иначе. Локально у меня тесты всегда
  компилировались отдельным вызовом `javac --release 17`, поэтому проблему
  свою же сборку через настоящий `mvn` я до сих пор не гонял и не ловил.
  Исправлено на двух уровнях: (1) добавлено `maven.compiler.testRelease=17`
  в `pom.xml` — maven-compiler-plugin с 3.6+ применяет его отдельно к
  `testCompile`, не трогая `release=8` основного кода; (2) на всякий случай
  весь `List.of(...)` в тестах заменён на `Arrays.asList`/`Collections.singletonList`
  — тесты теперь компилируются даже без фикса (1), под чистый Java 8.
